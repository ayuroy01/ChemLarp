# Audits

The audits to run before ChemLarp is called production-ready, what each covers, how to run it, and where it
stands. Findings are recorded in the "Findings" column; open items move to docs/GAPS.md once they are
understood. Status: **open** (not started), **partial**, **done** (date).

Started 2026-11-17. All seven CI jobs (Windows MSVC and MinGW, macOS, Linux, ThreadSanitizer,
AddressSanitizer/UBSan/LeakSanitizer, and the fuzzer) are green on commit `4ea4a5e`, as are the packages
and web workflows. Last run 2026-11-17: of 34 audits, 23 are done and 11 partial; none is untouched; nine defects were found and fixed (audits 1.1, 1.3, 1.5, 1.7 and 1.8).

| 1.3 | Memory errors | AddressSanitizer + LeakSanitizer in CI (`asan` job, Linux) | done 2026-11-17 | **Found a crash on its first run.** The canonical SMILES writer recursed once per atom, so a long chain overflowed the stack and killed the process — reachable from any SMILES, file or web input. The writer now follows the last child in a loop, so a chain costs one frame; branches still recurse and are refused past 4,000 nested deep with a diagnostic instead of crashing. | 1.5 | Fuzzing of every text input | `tests/fuzz_parsers.cpp`: one libFuzzer target covering 16 entry points (SMILES, SMARTS, MOL/SDF, PDB/mmCIF, mechanisms, flowsheet, lab, aqueous, MBAR, reactions, equilibrium, VLE, docking receptors and ligands), run in CI (`fuzz` job) with ASan and UBSan and a corpus seeded from the repository's own inputs | partial 2026-11-17 | **Found undefined behaviour on each of its first three runs, in three different parsers**: (1) a PDB coordinate of 2.16e8 converted to `int` when hashing atoms into grid cells; (2) the same file's grid hash multiplying signed values that overflowed; (3) a bracket atom's hydrogen count accumulated digit by digit with no cap, so `[CH999999999999]` overflowed before the range check could reject it — the isotope, charge, atom class and SMARTS's number() had the same shape and are capped too. Fixing it turned up a second conversion of the same kind in the neighbour query, where the converted value is also a loop bound in three dimensions, so a huge radius would have hung as well; both are clamped now and pinned by `protein_reader_survives_absurd_coordinates`. The saved crash input replays clean. Target wired into CI for 4 minutes a push. Locally, 57 million mutated inputs across four seeds under UBSan found no crash, no hang and no undefined behaviour (Apple's clang ships no libFuzzer, so the local run uses a random-mutation driver seeded from the same corpus). Still to do: a long soak (hours) with a kept corpus, and crashes triaged from a stored corpus rather than from scratch each run |
| 1.6 | Scientific validation | `make validate DATA=… PY=…` (`scripts/validate.py`): all suites against independent references | done 2026-11-18 | see docs/ARCHITECTURE.md.
